# APT 패키지 관리

많은 프로그램은 각 운영체제에서 원활하게 돌아가기 위해 필요한 프로그램 묶음을 정의하고, 한 번에 설치할 수 있도록 제공하는데 이를 **패키지(Package)**라고 합니다.
패키지는 소프트웨어를 실행하기 위한 모든 파일의 집합이며, 여기엔 실행 파일뿐만 아니라 설정 파일과 라이브러리 등도 포함됩니다.
동일하게 관리해야 할 패키지가 많아지는 경우 사용자가 일일이 파악하기 어렵기 때문에 주로 **패키지 매니저(Package Manager)**를 사용합니다.
이 챕터에서는 리눅스의 대표적인 패키지 매니저인 **APT(Advanced Package Tool)**의 사용법을 알아보겠습니다.

## 패키지란?
리눅스 패키지는 리눅스에서 프로그램을 실행하기 위해 필요한 파일들의 집합을 포함하는 설치 파일입니다. 쉽게 이해하면 윈도우의 설치 파일(.exe)이나 스마트폰의 앱과 같은 개념입니다.
패키지는 크게 '소스 패키지'와 '바이너리 패키지'로 구분됩니다.

- **소스 패키지**: 사용자가 직접 패키지를 컴파일해야 하므로 설치 시간이 오래 걸리고 컴파일 과정 중 오류가 발생할 확률이 존재한다는 단점이 있습니다. 다만 사용자가 소스코드를 자유롭게 변경하여 원하는 형태로 프로그램을 개조할 수 있다는 장점이 있습니다. (비유: 날것의 재료)
- **바이너리 패키지**: 이미 컴파일된 바이너리를 제공하기 때문에 설치 시간이 적게 걸리고 오류가 발생할 확률도 적습니다. 다만 컴파일된 바이너리가 필요로 하는 의존성 파일들을 제대로 제공하지 못하는 경우 오류가 발생할 수 있습니다. (비유: 3분 요리)

> 패키지 관리자를 사용하는 경우 대부분의 바이너리 패키지가 문제없이 설치되고 동작할 수 있으므로, 현대의 대부분의 리눅스 패키지는 바이너리 패키지 방식을 채택합니다.

패키지 관리 도구는 저수준과 고수준으로 나누어집니다.

- **저수준 패키지 관리 도구**: `dpkg`(Debian 계열)와 `rpm`(Red Hat 계열)이 있습니다. (우분투는 Debian 계열입니다.) 저수준 패키지 관리 도구는 단순히 개별 패키지를 설치, 제거할 목적으로 사용되며 패키지 간 의존성을 스스로 고려하지 않습니다.
- **고수준 패키지 관리 도구**: `apt`, `apt-get`과 `yum`, `dnf`가 있습니다. 고수준 패키지 관리 도구는 패키지 간 의존성을 스스로 파악하고 알아서 묶어 설치해 줍니다.
-> 일반적인 상황에서는 고수준 패키지 관리 도구를 선호합니다.

## apt & apt-get
`apt-get`이 먼저 만들어졌으며, `apt`는 `apt-get`이 가지는 단점을 해결하기 위해 등장했습니다.
과거에는 패키지 설치/업데이트/삭제는 `apt-get`으로, 패키지 조회는 `apt-cache`로, 설치된 패키지 확인은 `dpkg -l` 등으로 명령어가 분산되어 있었습니다. 이러한 기능들을 하나로 통합하고 사용 편의성을 높이기 위해 등장한 것이 바로 `apt`입니다.

`apt`는 `apt-get`보다 덜 세밀한 동작을 수행하지만 사용하기 훨씬 편리합니다. 반면 `apt-get`은 스크립트 작성 등 보다 정밀한 명령을 내리기에 용이합니다.
일반적으로는 `apt` 기능만으로도 충분하기 때문에 해당 명령어 기준으로 살펴봅니다.

- **APT**: Advanced Package Tool
- **사용법**: `apt [옵션] [명령어]`

> **Tip**: 프로그램을 설치하기 전 `sudo apt update -y && sudo apt upgrade -y`를 수행하면 저장소 정보가 최신화되어 패키지 설치 시 발생할 수 있는 오류를 예방할 수 있습니다.

# 네트워크
네트워크는 컴퓨터들이 서로 통신할 수 있도록 하기 위해 필요한 모든 것을 통칭하는 표현입니다.
일반 사용자들은 네트워크에 대한 복잡한 이해 없이도 LAN 선을 꽂거나 Wi-Fi에 연결만 하면 인터넷을 사용할 수 있습니다. 이는 운영체제와 프로그램들이 원활하게 네트워크를 사용할 수 있도록 백그라운드에서 지원해주기 때문입니다.

## 네트워크란?
네트워크는 계층 구조를 가지고 있으며, 각 계층은 자신의 바로 아래 계층과만 통신할 수 있습니다.
각 계층에서 사용하는 통신 규약이 있으며 이를 **프로토콜(Protocol)**이라고 부릅니다.
현대의 많은 프로그램은 **TCP/IP 프로토콜**을 사용하고 있습니다.

- **응용 계층**: 네트워크 서비스를 직접 제공하는 계층입니다.
- **전송 계층**: 수신자와 송신자가 올바른 정보를 송수신할 수 있도록 포트(Port) 정보 등을 포함한 세그먼트를 생성합니다.
- **네트워크 계층**: 송수신자를 구분하기 위해 IP 주소 등을 포함한 패킷을 생성합니다.
- **데이터 링크 계층**: 물리적인 데이터가 안전하게 전송되도록 제어합니다.
- **물리 계층**: 0과 1의 전기적 신호가 케이블(또는 무선)을 통해 물리적으로 전달되는 과정입니다.

## 네트워크 인터페이스 확인 (ifconfig)
네트워크 인터페이스는 컴퓨터나 네트워크 장비가 통신하기 위한 물리적인 또는 가상의 연결 지점을 의미합니다.
- 네트워크 인터페이스 카드(NIC)는 LAN, Wi-Fi에서 받은 전기 신호를 디지털 데이터로 변환합니다.
- 가상 머신(VM) 사용 시 로컬 머신과 가상 머신을 연결하는 가상 랜카드가 생성됩니다.

`ifconfig`는 **Interface Configuration**의 약자입니다. (사용을 위해서는 `sudo apt install net-tools`로 설치가 필요할 수 있습니다.)
명령어를 입력하면 활성화된 모든 네트워크 인터페이스의 정보가 출력됩니다.

- **활성화**: `ifconfig [인터페이스 이름] up`
- **비활성화**: `ifconfig [인터페이스 이름] down`

## 네트워크 접속 (nc)
`nc`는 **Netcat**의 줄임말로, TCP나 UDP 연결을 읽거나 기록하는 프로그램입니다.
사용자는 `nc`를 이용하여 TCP/UDP를 지원하는 네트워크 환경에 접속할 수 있습니다. (예: 드림핵의 포너블 문제 접속 등)
- **사용법**: `nc [옵션] [ip] [port]`

- `-l` 옵션이 없을 때: 클라이언트 역할로 다른 컴퓨터(서버)에게 먼저 연결을 시도합니다.
- `-l` 옵션이 있을 때 (Listen): 서버 역할로 포트를 열어두고 다른 컴퓨터가 접속할 때까지 대기합니다.

> 우분투에 설치되어 있지 않다면 `sudo apt install netcat`으로 설치합니다.
> **예시**: 터미널 1에서 `nc -lvp 12345`로 로컬 포트를 열고, 터미널 2에서 `nc localhost 12345`로 열린 포트에 접속할 수 있습니다.

## 네트워크 접속 (ssh)
`ssh`는 **Secure Shell**의 줄임말입니다. 과거 리눅스에서 셸 원격 접속에 사용하던 텔넷(Telnet)이 암호화를 지원하지 않아 보안에 취약했던 점을 보완하기 위해 등장한 프로토콜입니다.
`ssh`를 이용하면 사용자는 안전하게 원격으로 셸을 사용할 수 있습니다.
- 잘 알려진 포트(Well-known port)로 **22번**이 할당되어 있습니다.
- Diffie-Hellman Key Exchange(디피-헬만 키 교환) 방식 등 공개키/개인키 암호화 방식을 사용합니다.
- **사용법**: `ssh [옵션] [사용자 이름]@[서버 주소] [명령어]`

## 파일 다운로드 (wget)
`wget`은 **Web Get**의 약자로, 웹 상의 파일을 다운로드하기 위한 명령어입니다.
HTTP, HTTPS, FTP 프로토콜을 사용하는 사이트의 파일들을 다운로드할 수 있습니다.
- **사용법**: `wget [옵션] [URL]`

## 네트워크 데이터 전송 (curl)
`curl`은 **Client URL**의 약자로, 특정 프로토콜을 이용해 URL로 데이터를 전송하거나 가져올 때 사용합니다.
주로 HTTP, HTTPS, FTP, TELNET 등의 프로토콜을 지원하며 서버와 데이터를 주고받을 때 유용합니다.
- **사용법**: `curl [옵션] [URL]`

# 문서 편집기 (vim)
문서 편집기는 문서 파일을 편집하기 위해 쓰이는 소프트웨어를 의미합니다.
CLI(Command Line Interface) 환경에서는 마우스 클릭 기반의 문서 편집이 어렵습니다. 예를 들어 `cat`을 이용하여 문서를 작성하는 경우 엔터(Enter) 단위로만 작성 및 수정이 가능해 불편합니다.
이러한 문제를 해결하기 위해 프로그래머들은 CLI 환경을 위한 전용 편집기를 사용하며, 우분투에서 주로 사용하는 편집기로는 `vi/vim`, `emacs`, `nano` 등이 있습니다.

## vi, vim
`vi`는 **Visual Editor**의 약자입니다. 이후 수많은 개량형이 나오며 과거만큼 순수 `vi`가 많이 사용되지는 않지만, `vim`, `neovim` 등의 모태가 되는 만큼 가장 기본적이면서도 꼭 필요한 기능들을 모두 포함하고 있습니다.
`vim`은 'Vi IMproved'의 약자로 `vi`를 한 단계 더 발전시킨 편집기입니다.

`vim`은 크게 **명령 모드(Command Mode)**와 **편집 모드(Insert Mode)** 등 여러 상태를 가집니다.
- 프로그램을 실행하는 순간 기본적으로 **명령 모드**로 들어가게 됩니다. 명령 모드에서는 키보드 입력을 텍스트가 아닌 명령어로 처리합니다.
- 명령 모드에서 특정 키(예: `a`, `i`, `o`)를 누르면 **편집 모드**로 들어갈 수 있으며, 이때부터 텍스트 입력이 가능합니다.
- 편집 모드에서 텍스트 작성을 마친 후 `Esc` (또는 `Ctrl + c`)를 입력하면 다시 **명령 모드**로 돌아올 수 있습니다.

> **실습 예시**: 터미널에 `vim [파일명]`을 입력해 편집기로 들어오고, `a`나 `i`를 입력하면 편집 모드로 진입합니다. 이때 터미널 화면 왼쪽 아래에 `-- INSERT --`가 뜬 것을 확인할 수 있습니다. 명령 모드에서 입력받은 명령어를 통해 저장, 종료 등의 동작을 수행합니다.
