# 리눅스 셸 (Linux Shell)

서버 운영체제 시장에서 리눅스는 약 60% 이상의 점유율을 차지하고 있습니다. 또한, 리눅스를 포함한 현대의 많은 운영체제가 유닉스(Unix)에 뿌리를 두고 있기 때문에, 리눅스 사용법을 익히면 다른 운영체제도 수월하게 배울 수 있습니다.

> **학습 포인트:** 리눅스를 이해하면 전반적인 운영체제(OS)에 대한 이해도가 높아지며, 이후 보안 분야를 공부할 때 강력한 기초가 됩니다.

리눅스는 **오픈소스**이므로 사용자가 자유롭게 코드를 수정하고 재배포할 수 있습니다. 이러한 특징 때문에 클로즈드 소스(Closed Source) 운영체제와 달리 다양한 **배포판(Distribution)**이 존재합니다. 배포판은 기본 리눅스 커널을 바탕으로 각기 다른 기능, 패키지, 사용자 인터페이스(UI) 등을 결합하여 제공하는 운영체제를 의미합니다.

---

## 1. 셸(Shell)이란?

운영체제는 크게 **유저 레벨(User Level)**과 **커널 레벨(Kernel Level)**로 구분됩니다.
* **커널 레벨:** 일반 사용자가 직접 조작할 수 없는 영역입니다.
* **유저 레벨:** 사용자가 조작할 수 있는 영역입니다.

사용자가 운영체제를 제대로 제어하려면 커널과 유저 사이를 연결해 주는 프로그램이 필요한데, 이를 **셸(Shell)**이라고 부릅니다. 일반 사용자가 커널과 소통하기 위한 프로그램을 의미합니다.

> **셸(Shell)의 어원:** 영어로 '껍질'이라는 뜻이며, 운영체제의 핵심인 커널(Kernel, 알맹이)을 싸고 있는 껍데기 역할을 한다고 해서 붙여진 이름입니다.

모든 컴퓨터 사용자는 저마다의 셸을 사용하고 있으며, 특정한 형태가 정해져 있지 않고 종류도 매우 다양합니다. (예: GUI 바탕화면, 터미널 등) 셸을 잘 다루는 것은 운영체제를 잘 사용할 수 있다는 것과 같습니다.

### 셸의 주요 분류
1. **GUI (Graphical User Interface Shell):** 직관적으로 기능을 파악하고 사용하기 쉬운 장점이 있지만, 그래픽 리소스 소모가 큽니다.
2. **CLI (Command-Line Interface Shell):** 직관적이지 않고 명령어를 암기해야 하지만, 실행 속도가 빠르고 정밀한 자동화 작업에 유리합니다.

*보통 "리눅스에서 셸을 학습한다"고 하면 **CLI 셸**을 의미합니다.*

## 2. 셸의 종류와 터미널

### 터미널(Terminal)
터미널은 GUI 환경 위에서 CLI 셸을 사용할 수 있도록 도와주는 에뮬레이터 프로그램입니다. 기본 셸은 bash를 주로 사용하지만, 이 외에도 sh, zsh 같이 다양한 셸이 존재하고 각기 고유한 특징이 있습니다.

### 주요 셸 종류

#### 1. sh (Bourne Shell)
유닉스 버전 7의 기본 셸이며, 최초로 사용되던 Thompson shell 그리고 PWB shell을 대체하기 위해 등장했습니다.
* **지원 기능:** 기본적인 프로그램 실행, 기본적인 입출력, 환경 변수 설정, 셸 프로그래밍
* **실행:** 터미널에 `sh` 입력

#### 2. bash (Bourne-Again Shell)
Brian Fox가 `sh`를 대체하기 위해 작성한 유닉스 셸입니다. GNU 운영체제와 리눅스, macOS 등의 기본 셸로 탑재되었으며 이후 DOS와 마이크로소프트 윈도우로도 이식된 매우 대중적인 셸입니다. 일반 사용자가 기본적으로 로그인하면 볼 수 있는 셸이 바로 bash입니다.
* **추가된 주요 기능:**
  * 명령 히스토리 지원
  * Tab 자동 완성 지원 (명령어가 미완성된 상태일 때 키보드의 Tab 키를 두 번 누르면 자동 완성)
* **bash 로그인 시 시작 파일 자동 실행 순서:**
  1. `/etc/profile` (존재 시 읽은 후 실행)
  2. `~/.bash_profile`, `~/.bash_login`, `~/.profile`을 순차적으로 탐색해 **가장 먼저 발견되는 파일 하나만** 읽어서 개인 환경 설정을 적용.
  3. 로그인했던 셸이 종료하고 빠져나갈 때 `~/.bash_logout`이 존재하면 실행
  4. 비로그인 실행 시 `/etc/bash.bashrc`와 `~/.bashrc`가 존재하면 실행

#### 3. ash & dash
bash보다 경량화된 유닉스 셸입니다. 라이브러리 의존성이 상대적으로 적습니다.
* 플로피 디스크에 셸을 설치하는 등 용량이 제한된 상황에 사용
* 루트 사용자의 임시 셸 또는 `/bin/sh` 대체용

#### 4. zsh (Z Shell)
bash, ksh 등의 다양한 셸의 장점을 모아 만든 확장형 셸입니다. 커스텀하기 용이하며 설치도 간편합니다. macOS가 기본 셸로 사용하고 있습니다.

## 3. 리눅스 파일과 디렉터리

리눅스는 하드웨어 장치, 네트워크 소켓, 프로세스 정보 같은 시스템 자원들을 모두 **파일로 관리**하고, 디렉터리는 이러한 파일들을 체계적으로 구성하여 사용자가 쉽게 접근하고 관리할 수 있도록 도와줍니다.

### 파일 (File)
* 의미가 있는 정보를 모아둔 논리적인 단위입니다.
* **확장자 및 매직 넘버:** 운영체제는 파일의 맨 처음 특정 바이트만큼을 읽어 파일 종류를 구분(매직 넘버 혹은 파일 시그니처)하기 때문에 반드시 확장자명이 필요하지는 않습니다. (예: 윈도우에서는 `.docx`로 판별하지만, 리눅스는 파일 내부 데이터를 확인해 판별) 다만 파일 이름만 보고 쉽게 구분할 수 있도록 `.sh`, `.log` 같은 확장자를 붙이는 것이 일반적입니다.

### 디렉터리 (Directory)
* 파일을 분류하기 위해 사용하는 네임스페이스이며 윈도우의 폴더와 같습니다.
* 리눅스에서는 디렉터리를 **특수한 파일**로 취급합니다.
* 디렉터리와 파일들은 일반적으로 최상위 디렉터리(`/`)부터 시작하는 **트리 구조**를 형성합니다.

### 경로 표현 방식
* **절대 경로:** 최상위 디렉터리(`/`)부터 표시한 경로 (예: `/home/user1/dir1`)
* **상대 경로:** `/`부터 시작하지 않는 경로
  * `./` : 현재 사용자가 위치한 디렉터리
  * `../` : 상위 디렉터리
  * `~/` : 사용자의 홈 디렉터리

### 기본 파일/디렉터리 명령어

| 명령어 | 설명 | 예시 |
| :--- | :--- | :--- |
| **`pwd`** | 현재 작업 디렉터리(print working directory) 경로 확인 | `pwd` |
| **`cd`** | 디렉터리 경로 변경 (change directory) | `cd ../` (상위로 이동), `cd ~` (홈으로 이동) |
| **`ls`** | 디렉터리나 파일 목록 확인 (list segments) | `ls -al` |
| **`mkdir`** | 새로운 디렉터리 생성 | `mkdir new_folder` |
| **`rmdir`** | 생성한 디렉터리 삭제 | `rmdir empty_folder` |
| **`touch`** | 빈 파일 생성 (크기 0) | `touch file1.txt file2.txt` |
| **`cat`** | 파일 내용 읽기 및 쓰기 (concatenate) | `cat file.txt`, `cat > new.txt` |
| **`head`** | 파일의 앞쪽을 읽는 명령어 | `head -n 10 file.txt` |
| **`tail`** | 파일의 뒤쪽을 읽는 명령어 | `tail -f log.txt` |
| **`mv`** | 파일 경로 변경/이동 (move) | `mv old_path new_path` |
| **`cp`** | 파일 복사 (copy) | `cp -r dir1 dir2` (디렉터리는 `-r` 옵션 필요) |
| **`rm`** | 파일/디렉터리 삭제 (remove) | `rm file.txt`, `rm -rf dir1` (강제 삭제 시 주의) |

## 4. 파일 시스템과 링크 (Link)

리눅스(우분투 등)는 주로 **ext4** 파일 시스템을 사용하며, 각 파일들을 **inode**라는 메타데이터로 관리하여 각 파일은 고유한 inode를 가지고 있습니다.

### inode가 포함하는 정보
* inode 번호, 파일 모드(권한), 링크 개수
* 소유자와 그룹 ID, 파일 크기와 주소(데이터 저장 위치)
* 파일 최종 접근, 수정 정보
> **참조 횟수(Refcount):** inode를 참조하고 있는 파일의 개수입니다. 참조 횟수가 0이 되면 메모리 상에서 해당 객체를 제거합니다.

### 하드 링크 vs 심볼릭(소프트) 링크

| 구분 | 하드 링크 (Hard Link) | 심볼릭 링크 (Soft/Symbolic Link) |
| :--- | :--- | :--- |
| **설명** | 생성되는 파일의 inode를 링크하고자 하는 파일에 직접 연결. | 절대/상대 경로로 다른 파일을 참조 (윈도우 바로가기와 유사). |
| **특징** | 경로만 다를 뿐 사실상 동일한 파일. inode 링크 개수가 증가. | 새로운 inode를 생성하고, 링크 파일이 원본 파일을 가리킴. |
| **원본 삭제 시** | 하드 링크된 파일은 여전히 내용에 접근 가능. | 원본 파일 내용에 접근할 수 없음. |
| **명령어** | `ln [원본 파일] [링크 파일]` | `ln -s [원본 파일] [링크 파일]` |

### 파일 탐색: `find`
```bash
find [옵션] [탐색 시작 경로] [표현식]
# 예시: 와일드카드를 사용한 탐색
find . -name "*.txt"
```

## 5. 프로세스 생성 및 관리

평소 컴퓨터를 사용하여 수많은 프로그램을 실행합니다. 프로그램은 원래 저장 장치에 저장된 파일 형태로 존재하지만, 실행 명령을 받으면 컴퓨터는 주 기억 장치인 RAM으로 불러와 작동시킵니다. 이처럼 메모리에 적재된 실행 상태의 프로그램을 **프로세스(Process)**라고 부릅니다.
리눅스 명령어도 결국 프로그램이므로 명령어가 실행될 때 메모리에 올라가 프로세스로 작동합니다. 

### 프로세스란?
사용자 혹은 이미 실행되고 있는 프로세스가 프로그램을 실행하고자 하는 경우 운영체제에 실행 요청을 하며, 운영체제는 이 명령을 받아 프로세스를 생성합니다. 여러 프로세스가 동시에 실행되는 경우 운영체제가 적절하게 실행 순서를 조절합니다.

**프로세스의 5가지 상태**
1. **생성:** 프로세스가 생성되는 중
2. **실행:** 프로세스가 CPU를 점유하여 실제로 명령어들을 실행하는 중
3. **준비:** 프로세스가 CPU를 점유하기 위해 대기하고 있는 상태
4. **대기:** 프로세스가 입출력 대기 혹은 리소스 접근 불가 등을 이유로 작업을 수행할 수 없어 선수 작업이 완료되기를 대기하는 상태
5. **종료:** 프로세스가 종료되는 중

### 리눅스 프로세스
리눅스의 프로세스는 **PID(Process ID)**와 **PPID(Parent Process ID)**를 가집니다.
* **PID:** 현재 프로세스의 아이디
* **PPID:** 부모 프로세스의 아이디

리눅스는 새로운 프로세스를 생성할 때 `fork()`를 사용해 현재 프로세스를 복제하여 생성합니다. 이 때문에 프로세스 간 관계도를 그릴 경우 최상위 프로세스가 유일하게 존재하며 이를 **init 프로세스(PID 1)**라 합니다.
`fork()`로 생성된 자식 프로세스에서 `exec()`을 사용하면 프로세스 복제 후 다른 실행 파일의 내용으로 덮어쓰게 됩니다.

* **고아 프로세스:** 부모 프로세스가 먼저 종료된 자식 프로세스. 리눅스는 이런 프로세스들의 PPID를 1(init)로 변경하여 거둡니다.
* **좀비 프로세스:** 자식 프로세스는 종료되었지만 부모 프로세스가 자원을 수거하지 않아 그대로 남아있는 프로세스.

### 프로세스 관리 명령어
* **ps (Process State):** 현재 실행 중인 프로세스의 상태를 보여줍니다. (`ps [옵션]`)
* **htop:** 프로세스를 실시간으로 모니터링하기 위해 사용하는 GUI 스타일의 프로그램입니다.
* **jobs:** 사용자가 셸을 통해 실행한 프로세스 리스트와 상태를 출력합니다.

**포그라운드(Foreground)와 백그라운드(Background)**
* **포그라운드:** 사용자가 직접 상호작용하며 실행되는 프로세스
* **백그라운드:** 사용자와 직접 상호작용하지 않고 실행되는 프로세스 (`&` 기호를 명령어 끝에 붙여 실행)
* `ctrl-z`: 실행 중인 프로세스 정지
* `fg`: 정지된/백그라운드 프로세스를 포그라운드로 가져옴
* `bg`: 정지된 프로세스를 백그라운드에서 실행하도록 전환

**프로세스 종료 (kill, pkill)**
* `kill -[signal] [PID]`: 특정 프로세스에 시그널(예: 강제 종료 -9)을 보내 우선 처리하게 합니다.
* `pkill`: 프로세스 이름으로 종료

**프로세스 우선순위 (nice)**
* nice 값의 범위는 -20부터 19 사이이며 숫자가 낮을수록 우선순위가 높아집니다.
* 일반 사용자는 nice 값을 증가시키는 것만 가능하며, 감소는 root 권한이 필요합니다.
* `renice [nice] [PID]`: 현재 실행 중인 프로세스의 nice 수치 변경

## 6. 프로그램 실행과 환경 변수

### 프로그램 실행 방법
리눅스에서는 파일 데이터의 시작 부분에 위치한 **파일 시그니처(매직 넘버)**를 이용하여 파일 형식을 식별합니다. 
셸에서 실행 파일 경로를 입력하면 파일 시그니처를 확인한 후 `exec()`으로 프로세스화합니다. 리눅스는 **ELF(Executable and Link Format)** 형식의 실행 파일을 지원합니다. (윈도우 PE, macOS mach-O 등과 호환되지 않음)

### 환경 변수 (Environment Variable)
리눅스의 명령어(예: ls, cat)는 `/bin` 폴더 등에 있는 ELF 프로그램입니다. 절대 경로를 지정하지 않고 명령어만 입력해도 실행되는 이유는 **환경 변수(`PATH`)** 덕분입니다.
환경 변수는 컴퓨터에서 실행 중인 프로세스의 동작 방식에 영향을 미치는 값이며 일반적으로 키-값 쌍의 형태를 가집니다.

* **env:** 현재 환경 변수 출력
* **export:** 현재 셸에서 새로운 환경 변수를 설정 (`export KEY=VALUE`)
* **echo:** 환경 변수의 값 출력 (`echo $KEY`)
* **unset:** 설정된 환경 변수 삭제 (`unset KEY`)

## 7. 파일 디스크립터 (File Descriptor)

I/O(입력과 출력)는 컴퓨터와 현실을 연결하는 통로입니다. 사용자는 I/O에 직접 접근할 수 없으며 커널이 추상화한 값을 이용해 접근하는데, 이때 사용하는 값이 **파일 디스크립터(fd)**입니다.
프로그램이 운영체제에게 파일을 열어달라고 부탁하면, 운영체제는 파일을 준비하고 프로그램에게 숫자로 된 번호표(fd)를 줍니다.

* **File descriptor table:** 프로세스별 번호표 목록
* **Open file table:** 시스템 전체의 열린 파일 상태 목록
* **I-node table:** 하드디스크에 저장된 실제 파일 위치(inode)

### 기본 파일 디스크립터
프로세스에 기본적으로 할당되는 0, 1, 2번 파일 디스크립터입니다.
* **0 (stdin):** 표준 입력
* **1 (stdout):** 표준 출력
* **2 (stderr):** 오류(표준 에러) 출력

### 파이프와 리다이렉션
* **파이프 (`|`):** 이전 명령의 출력을 다음 명령어의 입력으로 제공하는 기능입니다.
* **리다이렉션:** 입력과 출력의 방향을 재지정합니다.
  * `<`, `<<`: 입력 방향 재지정
  * `>`: 출력 방향 재지정 (덮어쓰기)
  * `>>`: 출력 방향 재지정 (이어서 작성하기)

**grep 명령어**
표준 입력에서 들어오는 내용 중 정규식을 만족하는 문자열을 출력합니다.
* `grep [옵션] [패턴] [파일명/디렉터리]`
* 가장 많이 사용하는 형태: `[명령어] | grep [매칭문자]`

## 8. 사용자와 그룹 및 권한

현대의 거의 모든 운영체제는 다중 사용자를 지원합니다. 리눅스의 모든 파일은 소유자와 그룹, 권한을 가지며 이 값은 inode가 저장하고 있습니다.

### 유저와 그룹
* **유저:** 계정과 유사하며 하나의 유저는 여러 개의 권한을 가질 수 없습니다. (정보는 `/etc/passwd`, 암호는 `/etc/shadow`에 저장)
* **그룹:** 특정한 권한을 가진 사용자의 집단을 표현하기 위함이며 한 유저는 여러 그룹에 속할 수 있습니다. (정보는 `/etc/group`에 저장)
* **root 계정:** 관리자 권한 계정으로 운영체제에서 최고 권한을 가집니다. (`sudo`는 root 권한으로 명령어를 실행하게 해줌)

### 리눅스 파일 권한
소유자(u), 그룹(g), 일반 사용자(o)에 대해 읽기(r, 4), 쓰기(w, 2), 실행(x, 1) 권한을 부여합니다.
* 특수 권한: `setuid`(4), `setgid`(2), `sticky bit`(1)
* `s` 비트: 파일 실행 시 해당 주체의 권한으로 파일 실행
* `t` 비트(sticky bit): 일반 사용자가 디렉터리 내 파일을 생성할 수 있으나, 삭제는 root와 소유자만 가능

### 유저 및 그룹 관리 (root 권한 필요)
* **유저 생성:** `useradd [옵션] [유저 이름]` 또는 `adduser [유저 이름]`
* **유저 정보 변경:** `usermod [옵션] [유저 이름]`
* **비밀번호 변경:** `passwd [유저 이름]`
* **유저 삭제:** `userdel -r [유저 이름]` (-r 옵션은 홈 디렉터리도 함께 삭제)
* **그룹 생성:** `groupadd [그룹 이름]`
* **그룹 삭제:** `groupdel [그룹 이름]`

### 소유자, 그룹 및 권한 변경 명령어
* **chgrp:** 디렉터리/파일의 소유 그룹 변경 (`chgrp [옵션] [소유 그룹] [파일]`)
* **chown:** 소유자와 소유 그룹 동시 변경 (`chown [옵션] [소유자:그룹] [파일]`)
* **chmod:** 권한 변경 (`chmod [옵션] [권한] [파일]`)
  * 숫자 방식 (예: 755) 또는 문자 방식 (예: `g+w`) 사용
* **su (substitute user):** 다른 유저로 전환 (`su - [유저 이름]`)
